# 議事録 002: フェーズ1(game-core)の Codex 相互検証とレビュー指摘対応

- 日付: 2026-07-24
- 議題: フェーズ1完了レビューの指摘採否と、GDD §4 の仕様明確化

## 背景

計画に従い、(1) Codex MCP による実装後の相互検証、(2) 新規サブエージェント2体
(A: 仕様準拠 / B: コード品質)のレビューゲートを実施。
仕様書(GDD §4)の解釈に関わる指摘があったため議事録を作成する。

## 相談相手と意見の要旨

- **Codex MCP**: 未解放店員(直前の店員0体)でも資金があれば購入できるのは GDD §4 違反。
  ほか advance の NaN/Infinity ガード欠如、テストの穴3件(構造共有の参照検証、
  タップ式の境界、理論値=所持数での獲得0転生)
- **レビュアーA(仕様準拠)**: 数式・数値の不一致は0件。テスト欠落3件
  (マスタ8種+強化3種の値のピン留め検証、強化3段の購入シナリオ、解放判定の全数テスト)
- **レビュアーB(コード品質)**: buyGenerator がマスタ配列の index で state 配列に書き込むため
  順序ずれセーブで別スロットを破壊し得る(最重要)、readonly 欠落、純関数性が未検証、
  generatorCost を唯一のコスト経路とする契約の明文化、advance の dt 契約の明文化、
  判別力のないテスト1件と sqrt 境界の欠落

## 決定事項と理由

1. **GDD §4 に「未解放の店員は購入できない(ロジック層でも弾く)」を明記**(Codex 指摘)。
   従来はUI表示ルールとしてしか書かれておらず、コア層の挙動が未定義だった。
   表示だけで守る案は不採用 — デバッグ操作や将来のUI変更で破れるため
2. **buyGenerator / isGeneratorUnlocked を id ベースの参照に変更**(レビュアーB)。
   state 配列は「マスタと同順・同長」を invariant としつつ(types.ts に明記)、
   書き込み先の特定は id で行う多層防御とした。invariant の正規化はフェーズ2の
   deserialize / migrate が担う
3. **型の readonly 化を全面適用**(GameState / GeneratorState / マスタ定義)。
   構造共有前提の設計では外部ミューテーションが静かな破損になるため
4. その他の指摘(NaN ガード、コメントでの契約明文化、テスト9件追加)はすべて採用。
   唯一、tapGain 境界の「両分岐一致ケース(prod=150)」は判別力がないため削除
   (レビュアーBの指摘どおり)

## 影響

- GDD §4(購入ルールに1行追記)
- src/game-core/actions.ts(解放ゲート・id参照化)、advance.ts(有限性ガード)、
  types.ts / data/*(readonly)、テスト5ファイル(63件、全グリーン)
