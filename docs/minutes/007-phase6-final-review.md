# 議事録 007: フェーズ6(仕上げ・QA)と最終レビュー

- 日付: 2026-07-24
- 議題: ブラウザ非依存QAの実施内容、最終整合レビューの指摘対応、フェーズ6完了条件の再定義

## 背景

フェーズ6の作業のうちブラウザ必須の項目はこの環境で実施できない(議事録004)。
実施可能な範囲(バランススモーク・tick性能・時間加速フラグ・README)を完了させ、
最終レビューゲートとして全体整合レビュー(サブエージェント1体)を実施した。

## 実施したQA

- **バランススモーク**(balance.test.ts): 毎秒3タップ+即購入のアクティブプレイを
  シミュレートし、初回転生が30分〜6時間に収まることを回帰テスト化(実測で範囲内を確認)
- **tick 性能**: 全店員100体+猫玉50+全強化の状態で 10,000 tick < 500ms を固定
- **時間加速フラグ**: dev 限定 `?timescale=`(上限1000倍)。オフライン精算・保存は実時間のまま

## 相談相手と意見の要旨(最終整合レビュー)

指摘7件: (1) フェーズ6完了条件が自己参照で満たせない construction、フェーズ6固有項目の
繰り延べ漏れ、(2) フェーズ6のゲート記録・コミット未了(本議事録で解消)、
(3) バランス合格基準がテストにしか存在しない(ドキュメントが正の違反)、
(4) 数値表記「有効3桁」と実装(4桁帯あり)の不一致、(5) advance の dt 契約と
timescale の矛盾、(6) テストコメントの誤記、(7) README の Playwright 手順が対象読者不明瞭。
数値仕様(GDD §4〜§8)の全数照合・議事録001〜006の対応実施・設定残骸は問題なしと確認された。

## 決定事項と理由

1. **フェーズ6の完了条件を再定義**: ブラウザ非依存項目の完了+ブラウザ必須項目の
   保留リスト繰り延べをもって完了とし、保留リストの消化は
   **ユーザー環境での受け入れ確認** と位置づける(自己参照の解消)
2. **【仕様追記】GDD §8**: 初回転生の目安「アクティブ30分〜6時間」を明記し、
   バランステストの合格基準の出典をドキュメント側に置いた
3. **【仕様修正】GDD §10 / TECH §12**: 「有効3桁(整数部4桁の帯のみ4桁)」に精緻化。
   実装側が自然(0.123億のような表記を避ける)なため仕様側を合わせた
4. 残る指摘(コメント整合・README の書き分け)は全て採用
