# 議事録 005: フェーズ4(React UI)のレビュー指摘対応

- 日付: 2026-07-24
- 議題: UI レビュー3本(仕様準拠/コード品質/UX)の指摘採否と仕様の微修正

## 背景

フェーズ4完了レビューとして新規サブエージェント3体を並列実施(UI フェーズのため UX 観点を追加)。
計22件(重複除く)の指摘のうち、仕様書の修正を伴うものが3件あったため議事録を作成する。

## 相談相手と意見の要旨

- **仕様準拠(5件)**: HUD がセーフエリアで高さ不足(レイアウトのしわ寄せ先が仕様と逆)、
  state 全体購読は TECH §6 逸脱、format の1万境界で「10000」表示、
  未解放時に「獲得予定: 0」を見せている、レート制限タップが totalTaps に載らない
- **コード品質(9件)**: モーダル多重表示が未調停、フォーカス管理なし、キーボード操作不能、
  100dvh フォールバック欠如、float の setTimeout リーク、ARIA タブが中途半端、ほか
- **UX(8件)**: タップ領域とタブバー隣接で誤爆、disabled ボタンのコントラスト 1.8:1、
  マイルストーンが不可視、リセット確認の肯定ボタン位置が危険、44px 未満のタップ目標、
  転生解放までの残量が計算必要、レート制限時の「…」が故障に見える、ほか

## 決定事項と理由

1. **全22件を採用**(対立なし。数件は同一根因の重複)
2. **【仕様修正】GDD §8**: 解放前は獲得予定を表示しない(0表示は動機を殺す)。
   「超えると」→「達すると」に統一(gte 実装との境界整合)
3. **【仕様確定】GDD §12**: 総タップ回数はレート制限で収入0のタップも数える
   (「総タップ」の語義どおり。収入付与のみ数える案は不採用 — 統計として不自然)
4. **【仕様修正】TECH §11**: HUD は内容駆動(min 10%)・canvas flex-1 が
   セーフエリアを吸収する構成に明文化(10%固定+inset内包は物理的に収まらない)
5. 再レンダリング対策は「セレクタで表示用プリミティブへ落として JSON 比較」方式で統一
   (HUD は表示文字列 select)。行数規模的に実害は小さいが、フェーズ5で装飾が増える前に
   構造として正しておく
6. UX 対応: タップ領域下端に20pxの不感帯、44px タップ目標、disabled の濃色文字、
   「あと◯体で生産×2」表示、破壊操作は控えめ導線+肯定位置に安全な選択肢、
   レート制限時はフロート非表示(押下演出のみ)

## 影響

- GDD §8・§12、TECH_DESIGN §11
- src/ui/ 全コンポーネント、GameRoot.module.css、format.ts、store/gameStore.ts(tap 計上)
- テスト 134 件全グリーン(format 境界1件追加)
