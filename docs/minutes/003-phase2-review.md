# 議事録 003: フェーズ2(セーブ・オフライン)のレビュー指摘対応と仕様変更

- 日付: 2026-07-24
- 議題: 時計改ざん対策の仕様変更、シリアライズ堅牢化、version 欠落の扱いの確定

## 背景

フェーズ2の完了レビューとして Codex MCP + サブエージェント2体(A: 仕様準拠 / B: コード品質)
を実施。**GDD/TECH_DESIGN の仕様自体を変える必要のある指摘**が2件あったため議事録を作成する。

## 相談相手と意見の要旨

- **Codex MCP**: (1) 時計を「進める→収益取得→戻す→また進める」の往復で
  オフライン収益を反復取得できる(従来仕様の「未来 savedAt は now で上書き」が原因)。
  (2) `new Decimal('Infinity')` は mantissa/exponent とも有限ペアになり検証を素通りする。
  (3) 個数系が安全整数範囲外を受理する
- **レビュアーA(仕様準拠)**: Infinity 素通り(Codexと同指摘)、serialize が保存時刻を
  刻まないため次回起動時に二重収益化する、version 欠落の扱いが TECH §9 の
  「欠落は補完」と矛盾、モーダル抑止(0<獲得<1)と savedAt 事後条件のテスト欠落
- **レビュアーB(コード品質)**: `'1e9e9'` が黙って 1e9 に誤パースされる(throw 前提が崩れている)、
  非有限 nowMs で savedAt が NaN 汚染、e15〜20帯のラウンドトリップ未検証、
  敵対的文字列テスト皆無、構造共有の参照未検証、migrate が未知キーを素通し

## 決定事項と理由

1. **【仕様変更】savedAt を単調非減少にする**(GDD §7 / TECH §4 改訂)。
   従来の「未来 savedAt は now で上書き」は時計往復エクスプロイトの温床だった。
   巻き戻し時は据え置き、実時間が追いつくまで収益0とする。
   別案の「最高到達時刻を別フィールドで永続化」は SaveData のスキーマ追加になるため不採用
   (savedAt 自体を透かしにすれば同等の防御になる)
2. **【仕様変更】serialize は保存時刻を引数に取り `savedAt = max(state.savedAt, now)` を
   スタンプする**(TECH §9 改訂)。刻み忘れによる二重収益化をAPI設計で防ぐ
3. **【仕様確定】version 欠落・非整数は「破損扱い」に倒す**(TECH §9 に但し書き)。
   判別子のないデータをフィールド補完するのは危険。実装は現状維持、仕様側を修正
4. デシリアライズは構築前の形式検証(正規表現)を必須化。break_infinity が
   'Infinity' を有限ペアで受理し '1e9e9' を誤パースする実挙動を確認したため
5. その他(非有限 nowMs ガード、安全整数チェック、migrate の既知キー抽出、
   テスト12件追加)はすべて採用。e15〜20帯のラウンドトリップは実測で不一致0を
   確認した上で回帰テストとして固定

## 影響

- GDD §7(時計改ざん対策の書き換え)
- TECH_DESIGN §4(単調非減少)、§9(serialize 契約・形式検証・version 但し書き)
- src/game-core/offline.ts、save/serialize.ts、save/migrate.ts、テスト2本(計93件グリーン)
- フェーズ3の persistence 実装は「保存時も max 規則」を引き継ぐこと
