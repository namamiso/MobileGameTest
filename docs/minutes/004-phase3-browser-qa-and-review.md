# 議事録 004: 実ブラウザ検証不能への対応と、フェーズ3配線の設計修正

- 日付: 2026-07-24
- 議題: (1) 実行環境にブラウザがなくフェーズ3の完了条件(手動確認)を満たせない問題、
  (2) フェーズ3レビューで判明した配線層の設計欠陥

## 背景

フェーズ3の完了条件はブラウザでの手動確認だが、この実行環境では Playwright chromium が
システムライブラリ(libatk 等)不足で起動できず、sudo 権限もシステムブラウザもない。
計画の「フェーズ完了条件を満たせない事態」に該当するため、サブエージェントに相談した。
併せて実施したレビュー2本(仕様準拠/コード品質)が配線層の重大欠陥を検出した。

## 相談相手と意見の要旨

- **QA方針相談エージェント**: 推奨は「A+B の組み合わせ」— 実ブラウザ確認は保留リスト化して
  フェーズ6冒頭でユーザーに `sudo npx playwright install-deps chromium` を依頼、
  併せて jsdom で配線ロジックを統合テスト。自走停止(案C)は計画の趣旨に反し不採用
- **レビュアーA(仕様準拠)10件**: hidden 中の autosave が savedAt を前進させ
  長時間放置の収益がほぼ全損する(最重要)、保存ガードが `now` 混入で実質無効、
  ロック取得前の無条件セーブ、リーダー昇格時の再読込が未定義、ほか
- **レビュアーB(コード品質)10件**: 共通根因は「savedAt が『永続化成功時刻』と
  『収益計上済み透かし』の二役を兼ねている」こと。リーダー交代での巻き戻り(最重要)、
  保存失敗時の二重加算、サスペンド(visibilitychange なしの rAF 停止)での収入消失、
  check-then-set レース、pagehide 未処理、ほか

## 決定事項と理由

1. **QA方針は相談エージェント推奨を修正採用**: 実ブラウザ確認は保留チェックリストとして
   計画のフェーズ6に明記し、自走を継続する。ただし jsdom は導入しない —
   レビュー対応で配線ロジックを `store/session.ts` に抽出した結果、
   検証したい挙動(起動・昇格・精算・透かし)が素の vitest で直接テストできるようになり、
   jsdom で増える検証面が残らないため(イベント登録の1行ラッパーのみ)
2. **【設計変更】savedAt の意味を「収益計上済み透かし」に統一**(TECH §9 に新設)。
   markSaved は保存成否と無関係に刻む。hidden 中の autosave は禁止
3. **【設計変更】リーダーのライフサイクルを明文化**(TECH §8 改訂):
   起動はロック取得→ロードの順、非リーダーは精算なし表示ロード、
   昇格時はディスクから再同期、保存ガードは透かし同士の比較、
   ロックは書き込み後読み戻しで確定、SAVE_KEY の storage イベント追従、pagehide 対応
4. **【設計変更】サスペンド検出**(TECH §4 追記): フレーム間の壁時計ギャップ>5秒で
   tick せず「最後の生きたフレーム時刻」基準の精算に切り替える
5. タップのレート制限窓は performance.now 系に統一し、ストアのクロージャ内へ移動

## 影響

- TECH_DESIGN §4 / §8 / §9、IMPLEMENTATION_PLAN(フェーズ3完了条件の差し替え、
  フェーズ6に保留チェックリストと install-deps 依頼を明記)
- src/store/session.ts(新規)、persistence.ts、tabLock.ts、gameStore.ts、
  loop/useGameLoop.ts、ui/GameRoot.tsx
- テスト 123 件全グリーン(session 12件・persistence 失敗パス2件を追加)
- **ユーザーへのお願い(フェーズ6冒頭)**: `sudo npx playwright install-deps chromium`
  を実行できる状態にしていただくと実ブラウザQAが可能になります
