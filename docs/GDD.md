# ねこ茶屋 〜まったり放置経営〜 ゲームデザインドキュメント (GDD)

- バージョン: 0.2(設計レビュー反映版 — 曖昧箇所の明確化と数値調整のみ。機能の増減なし)
- 対象プラットフォーム: モバイルブラウザ(縦持ち・片手操作)。デスクトップブラウザでも動作
- 技術スタック: Next.js + PixiJS(詳細は `TECH_DESIGN.md`)

## 1. コンセプト

江戸風の茶屋をねこたちが切り盛りする放置経営ゲーム。プレイヤーは茶屋の主人として、
ねこ店員を雇い、店を拡張し、放置している間も売上(小判)が貯まっていくのを眺めて癒される。

- ジャンル: 放置系クリッカー / インクリメンタルゲーム
- 1セッション想定: 30秒〜3分。1日に数回開いて回収・強化するプレイスタイル
- ターゲット: カジュアル層。数値インフレの気持ちよさ+ねこの可愛さで引っ張る

## 2. コアループ

```
タップで小判を稼ぐ
   ↓
ねこ店員を雇う(自動で小判を生産)
   ↓
売上で店員を増員・強化 → 生産量が指数的に増える
   ↓
成長が鈍化したら「のれん分け」(転生)で猫玉を獲得
   ↓
猫玉の永続ブーストで最初からより速く周回
```

## 3. 通貨

| 通貨 | 入手方法 | 用途 | リセット |
|------|---------|------|---------|
| 小判 | タップ / ねこ店員の自動生産 / オフライン収益 | 店員の雇用・タップ強化の購入 | のれん分けで0に戻る |
| 猫玉 | のれん分け(転生)時に累計獲得小判に応じて獲得 | 永続の生産倍率(1個につき +10%) | リセットされない |

- **累計獲得小判(lifetimeKoban)**: タップ・自動生産・オフライン収益のすべてを合算した
  **全期間累計**。のれん分けでもリセットされず、周回をまたいで増え続ける(猫玉計算の入力)

## 4. ねこ店員(ジェネレーター)

8種類。上位ほど基礎コスト・基礎生産が高い。購入するたびにコストが増加する。

| # | 名前 | 基礎コスト(小判) | 基礎生産(小判/秒) |
|---|------------|------------|------------|
| 1 | 子ねこ店員 | 15 | 0.1 |
| 2 | 茶運びねこ | 100 | 1 |
| 3 | 看板ねこ | 1,100 | 8 |
| 4 | 板前ねこ | 12,000 | 47 |
| 5 | 女将ねこ | 130,000 | 260 |
| 6 | からくり茶釜 | 1,400,000 | 1,400 |
| 7 | ねこ神社 | 20,000,000 | 7,800 |
| 8 | 招き猫像 | 330,000,000 | 44,000 |

### 数式

- n体目の購入コスト: `cost = baseCost × 1.15^owned`(Cookie Clicker 系の標準成長率)
- 種別の生産量: `production = baseProd × owned × milestoneMult × globalMult`
- マイルストーン倍率: 各店員の所持数が **10 / 25 / 50 / 100 体** に達するごとに、その店員の生産 ×2
  (最大 ×16。所持数からの純導出であり、独立した状態としては保存しない)
- グローバル倍率: `globalMult = 1 + 0.10 × 猫玉所持数`(タップ強化は含まない。§6 参照)

### 購入ルール

- 購入は **x1 のみ**(まとめ買いなし)
- 購入ボタンは `所持小判 ≥ 次のコスト` のとき活性。不足時はグレーアウト(コストは常時表示)
- リスト表示は段階解放: 直前の店員を1体以上所持すると次の店員の行が出現。
  未解放の次の1種のみ「???」のシルエット行で先出し表示する
- 未解放の店員は購入できない(UI 表示だけでなくゲームロジック層でも弾く)

## 5. タップ

- 画面のねこ(店の中央)をタップすると小判を獲得
- タップ収入: `tapGain = max(1 × globalMult, 総生産/秒 × 1%) × tapMult`
  - 「総生産/秒」はマイルストーン・globalMult 適用後の最終値
  - 下限側にも globalMult を乗せることで、転生直後(生産0)でも猫玉の恩恵が出る
  - `tapMult` はタップ強化(§6)の倍率。端数は Decimal のまま加算し、表示のみ丸める
- **受付レート上限: 15回/秒**。超過分は演出のみ再生し収入は0(オートクリッカー対策)
- マルチタッチは同時1点のみ判定
- タップ時はねこが鳴く・小判が跳ねるなどのフィードバック(PixiJS 側で演出)

## 6. 強化(タップ強化)

[強化]タブで購入できる買い切りアップグレード。テスト版は以下の3段階のみ。

| 名前 | コスト(小判) | 効果 |
|------|------------|------|
| 鈴 | 1,000 | タップ収入 ×2 |
| 座布団 | 50,000 | タップ収入 ×2 |
| 金の首輪 | 2,500,000 | タップ収入 ×2 |

- 効果は乗算(全購入で `tapMult = 8`)。タップ収入にのみ効き、自動生産には影響しない
- 購入順は任意ではなく上から順(前段購入が次段の解放条件)
- **のれん分けでリセットされる**(小判で買い直す)

## 7. オフライン収益(放置の核)

- 基準時刻は最終保存時刻(`savedAt`)。復帰・起動時に経過時間から一括計算する
- 計算式: `獲得 = min(経過秒, 8時間) × 総生産/秒 × 0.5`
  - **クランプが先**(8時間で頭打ちにしてから 50% を掛ける。実質最大4時間分)
  - 効率 50% はオンラインで眺めるインセンティブを残すため
- **短時間離席の救済**: 非表示時間が **60秒未満** の場合はオフライン扱いにせず、
  経過分を効率 100% で無音加算する(モーダルなし)
- 60秒以上の場合は「おかえりなさい!○○小判 貯まりました」モーダルで一括受取。
  ただし獲得が1小判未満のときはモーダルを出さず無音加算する
- **時計改ざん対策**: 経過秒は `clamp(now − savedAt, 0, 8時間)`。`savedAt` が未来
  (`savedAt > now`)の場合は収益0。このとき `savedAt` は**巻き戻さない**
  (`savedAt = max(savedAt, now)` の単調非減少を保つ)。時計を進めて収益を取り、
  戻してまた進める往復での反復取得を防ぐため、実時間が `savedAt` に追いつくまで
  オフライン収益は発生しない

## 8. のれん分け(プレステージ)

- 解放条件: 累計獲得小判が 1,000,000 に達すると転生パネルに獲得予定数が表示される。
  それまでは解放条件と残り小判のみ案内する(獲得予定 0 を見せない)
- 獲得猫玉: `max(0, floor(sqrt(lifetimeKoban / 1,000,000)) − 現在の所持猫玉数)`
  - 猫玉は消費されない通貨のため「現在の所持数 = これまでの累計獲得数」が成立し、
    この式は Cookie Clicker 方式の「理論総数との差分付与」になる
- **転生ボタンは獲得予定が1個以上のときのみ活性**(獲得0での全損転生を防ぐ)
- 押下時は確認ダイアログを必須とする。失うもの(小判・店員・マイルストーン・タップ強化)と
  獲得猫玉数を明示し、2タップで確定
- リセット対象: 小判・店員(マイルストーンは owned=0 の結果として消える)・タップ強化
- 保持対象: 猫玉・統計(§12)
- 猫玉1個 = 全生産 +10%(永続・加算。globalMult に反映)

## 9. 画面構成(1画面完結)

```
┌─────────────────────┐
│ 所持小判 / 毎秒生産量 (HUD)      │  ← React(高さ 10%)
├─────────────────────┤
│                     │
│   茶屋のシーン(PixiJS Canvas)   │  ← タップ領域(高さ 50%)
│   雇った店員のねこが表示される       │
│                     │
├─────────────────────┤
│ [店員] [強化] [のれん分け] タブ    │  ← React(高さ 40%)
│  店員リスト(購入ボタン付き)       │
└─────────────────────┘
```

- 縦3段の比率レイアウト(10% / 50% / 40%)。基準ビューポート幅 390px、
  ノッチ・ホームバーはセーフエリア対応(詳細は TECH_DESIGN §11)
- 店員リストの各行: 名前 / 所持数 / その種の合計生産/秒 / 現在コスト(購入ボタン兼用)
- キャンバス内のねこは **1種につき最大5体** 表示。6体目以降はグループ右上の「×N」バッジで表現
  (全種で最大40スプライト)
- ねこのアセットはテスト版では色違いのプレースホルダーで良い

## 10. 数値表記

- 1万未満: 整数表示(切り捨て)
- 1万以上: 日本語単位(万・億・兆・京 … **無量大数 = 1e68 まで**)+ 有効3桁
  (例: `1.23万`、`12.3億`)
- **1e72 以上は指数表記にフォールバック**(例: `1.23e75`)
- 丸め方向: 残高・生産量は **切り捨て**、コスト表示は **切り上げ**
  (「買えるように見えて買えない」を防ぐ。購入可否判定は Decimal の正確な比較で行う)
- 内部値は常に Decimal のまま保持し、丸めは表示時のみ

## 11. セーブ

- 自動保存: 10秒ごと+タブ非表示時(visibilitychange)
- 保存先: localStorage(テスト版)。スキーマにバージョン番号を持たせマイグレーション可能にする
- 初回起動(セーブなし)は初期状態(小判0・全店員0・猫玉0・`savedAt = now`)で開始し、
  オフライン計算・モーダルは走らせない
- セーブ破損時は元データを別キーに退避してから初期化し、起動時モーダルで通知する
- 手動リセット(全削除)を設定メニューに用意

## 12. 統計(転生でリセットされない値)

テスト版で保持する統計は以下の4つのみと定義する。

- 累計獲得小判(lifetimeKoban)
- 転生回数(prestigeCount)
- 総タップ回数(totalTaps)— レート制限で収入0だったタップも数える
- プレイ開始日時(startedAt)

## 13. スコープ外(テスト版で作らないもの)

- 広告・課金・プッシュ通知
- 実績、イベント、ガチャ、サウンド以外の演出強化
- サーバー保存・アカウント連携(すべてクライアント完結)
